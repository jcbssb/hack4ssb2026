# 07 Multi-Repo Ecosystem & Decoupled Architecture

This document defines the target productization architecture for separating **Skjemantikk** into a modular, multi-repo open ecosystem.

---

## 1. Architectural Philosophy

1. **AST is Core & Canonical**:
   The Dialogue Schema DSL AST (`skjemantikk-core`) is completely generic. It knows **nothing** about Altinn, XML4DR, PDF layouts, or React rendering. It defines only:
   - Dialogue structure (Metadata, Steps, Bolks, Questions, Matrices).
   - Expressions and Arithmetic Operations.
   - Calculations and Dependency Order.
   - Constraints, Validation Rules, and Severities (Error vs Warning).
   - Visibility Predicates and Guidance Rules.

2. **Compilers are Independent Plugins**:
   Target platforms (Altinn 3, DigDir Designsystemet, future targets) live in their own dedicated repositories as pure AST consumers.

3. **Zero Code Duplication via Shared Contracts**:
   TypeScript/JavaScript tools share a single published contract (`@skjemantikk/types` and `@skjemantikk/eval`) derived directly from the core JSON Schema.

4. **Designsystemet Everywhere**:
   All visual UI tools (`skjemantikk-simulator`, `skjemantikk-skjemakart`, and applications generated by `skjemantikk-compiler-designsystemet`) share DigDir's Designsystemet tokens, components, and UX patterns.

### Repo 1: `skjemantikk-core`
- **Language**: Haskell (or Rust if rewritten for single-binary portability).
- **Contents**:
  - `SchemaDSL.Types`: The pure Dialogue AST.
  - `SchemaDSL.Eval`: Canonical evaluation, dependency graph ordering, and constraint checker.
  - `SchemaDSL.JSON`: Strict JSON encoder/decoder.
  - `dialogue.schema.json`: The formal JSON Schema definition.
- **Artifacts**:
  - `schema-dsl-cli`: Validate schema JSON, verify calculation graphs, format ASTs.
  - npm package build: emits `dialogue.schema.json` for code generation.

### Shared npm Package: `@skjemantikk/types` & `@skjemantikk/eval`
- **Purpose**: Prevent code duplication across TypeScript/JavaScript tools.
- **Contents**:
  - Auto-generated TypeScript definitions via `json-schema-to-typescript` from `dialogue.schema.json`.
  - Canonical JavaScript/TypeScript evaluator (`eval.ts`), validated against Haskell golden tests.
  - Shared page-partitioning logic (`pages.ts`).
- **Consumers**: `skjemantikk-simulator`, `skjemantikk-skjemakart`, `skjemantikk-compiler-designsystemet`.

### Repo 2: `skjemantikk-compiler-altinn`
- **Role**: Compiles core Dialogue AST into Altinn 3 Studio App artifacts.
- **Input**: `dialogue.json` (satisfying `dialogue.schema.json`).
- **Output**:
  - `App/ui/layouts/*.json` (one layout per bolk, Grid components for matrices).
  - `App/ui/Settings.json` (page ordering and pagination).
  - `App/models/*.cs` and C# data model bindings.
  - `App/config/texts/resource.*.json` (labels, help texts, validation error messages).
  - Altinn hidden/required expressions compiled from DSL predicates.
- **CLI**:
  ```bash
  skjemantikk-altinn compile schema.json --target-app /path/to/altinn-app
  ```

### Repo 3: `skjemantikk-compiler-designsystemet`
- **Role**: Scaffolder and code-generator for standalone modern web forms using DigDir Designsystemet.
- **Input**: `dialogue.json`.
- **Output**:
  - Complete, runnable Vite + React + TypeScript repository.
  - `@digdir/designsystemet-react` and `@digdir/designsystemet-css` styling.
  - Typed forms with multi-page bolk navigation, auto-fill calculations, and inline validation.
  - Reusable form component library.
- **CLI**:
  ```bash
  skjemantikk-ds scaffold schema.json --out ./my-digdir-form
  ```

### Repo 4: `skjemantikk-simulator`
- **Role**: Interactive web runner and development harness for DSL schemas.
- **Tech Stack**: React 18, Vite, DigDir Designsystemet.
- **Dependencies**: `@skjemantikk/types`, `@skjemantikk/eval`.
- **Features**:
  - Live inspection of answers, derived values, and calculation order.
  - URL deep-linking (`?schema=...&page=...&field=...#...`).
  - Pulsing highlight and autofocus on jump targets.

### Repo 5: `skjemantikk-skjemakart`
- **Role**: Architectural visualization and audit relation map.
- **Design Alignment**: Upgraded from raw custom CSS to **DigDir Designsystemet** tokens (`@digdir/designsystemet-css`), consistent colors, cards, and buttons.
- **Dependencies**: `@skjemantikk/types`, consuming `facts.json` and `align.json`.
- **Capabilities**:
  - Visual grid of sections and cells.
  - Upstream/downstream calculation traces.
  - Constraint partner graphs.
  - Seamless jump link to `skjemantikk-simulator`.

### Repo 6: `skjemantikk-audit` (Legacy & Ingestion Tools)
- **Role**: Extracting facts from legacy forms (XML4DR, PDF, OCR, screenshots) and computing alignment diffs against the DSL AST.
- **Outputs**: `facts.json`, `align.json`, and `findings.json`.

## 3. Consumer "Slices": How Others Use It

A consumer only checks out and runs the slice matching their immediate problem:

### Slice A: "I want to author a form and deploy to Altinn 3"
1. Author form in DSL (JSON or assisted by an LLM with `dialogue.schema.json`).
2. Run `skjemantikk-compiler-altinn compile my-form.json --target-app ./altinn-studio-app`.
3. Done: no simulator, no XML4DR tools, no Haskell toolchain needed if using prebuilt CLI.

### Slice B: "I want a custom web form in DigDir Designsystemet"
1. Author form in DSL.
2. Run `skjemantikk-compiler-designsystemet scaffold my-form.json --out ./my-form-app`.
3. `cd my-form-app && npm install && npm run dev`.
4. Deploy wherever standard React apps run.

### Slice C: "I have a legacy form (PDF/XML) and need to audit & modernize it"
1. Ingest legacy form with `skjemantikk-audit` $\to$ `facts.json`.
2. Author draft DSL $\to$ `schema.json`.
3. Run `skjemantikk-audit align` $\to$ open `skjemantikk-skjemakart` to verify field matches.
4. Test interactions live in `skjemantikk-simulator`.
5. Compile to Altinn or Designsystemet once audited.

### Slice D: "I want to build a compiler for another platform (e.g. SurveyMonkey, Plone, PDF)"
1. Consume standard `dialogue.schema.json`.
2. Read the JSON AST in Python, Go, TypeScript, C#, etc.
3. Emit output for the target platform.
